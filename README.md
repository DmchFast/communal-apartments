## Назначение

Приложение для учёта показаний счётчиков воды, электроэнергии, газа и других коммунальных ресурсов. Позволяет фиксировать показания, рассчитывать расход, вести историю и рассчитывать платежи по тарифам.

**Целевая аудитория:**

- Жильцы квартир и частных домов
- Семьи, планирующие бюджет на коммунальные услуги
- Управляющие компании

---

## Предметная область

Сервис предоставляет возможность добавлять счётчики, вносить показания с автоматической фиксацией даты и времени, проверять корректность (новое показание не может быть меньше предыдущего), вычислять расход как разность двух последних показаний и рассчитывать платёж по установленному тарифу. Данные каждого пользователя хранятся в отдельных JSON-файлах.

**Главная сущность — `Payment` (платёж).** Человек платит за показания, показание содержит счётчик (характеристики прибора), а платёж объединяет показания и тариф в итоговую сумму к оплате.

---

## Основные сущности

- **Пользователь** — владелец счётчиков и показаний (вход по имени)
- **Счётчик** — устройство учёта (название, единица измерения, тариф)
- **Показание** — значение с датой и временем снятия; содержит ссылку на объект `Meter`
- **Платёж** — **главная сущность**: сумма к оплате на основе показаний и тарифа

### Иерархия сущностей

```
Payment  (главная сущность)
  └── Reading (текущее и предыдущее показания)
        └── Meter (характеристики прибора)
```

---

## Основные классы

### `Payment` — платёж (главная сущность)

Объект представляет платёж за показания счётчика.

**Атрибуты:**

- `current` — текущее показание (`Reading`);
- `previous` — предыдущее показание (`Reading`);
- `meter` — счётчик (`Meter`), взятый из показания;
- `consumption` — расход между показаниями;
- `tariff` — тариф счётчика;
- `amount` — сумма к оплате (`None`, если не хватает данных или тарифа).

**Методы:**

- `__str__()` — человекочитаемое описание платежа;
- `Payment(current, previous=None, meter=None)` — конструктор с валидацией:
  - показания должны относиться к одному счётчику;
  - текущее показание не может быть меньше предыдущего;
- `create_payment(readings, meter_id)` — фабричная функция модуля,
  строит платёж по последним двум показаниям счётчика.

---

### `Meter` — счётчик

Объект представляет устройство учёта коммунального ресурса.

**Атрибуты:**

- `id` — уникальный идентификатор счётчика;
- `name` — название счётчика;
- `unit` — единица измерения;
- `tariff` — тариф за единицу ресурса (`None`, если не установлен).

**Методы:**

- `__str__()` — строковое представление вида `[1] Вода (м^3), тариф: 45.50 руб.`;
- `set_tariff(tariff)` — установить или сбросить тариф;
- `from_data(meter_id, data)` — создать объект из JSON (`@classmethod`);
- `to_dict()` — преобразовать объект в данные для JSON.

---

### `Reading` — показание

Объект представляет одно показание счётчика и **содержит объект `Meter`** — характеристики прибора.

**Атрибуты:**

- `meter` — объект `Meter`, к которому относится показание;
- `meter_id` — ID счётчика (дублирует `meter.id` для быстрого поиска);
- `value` — значение показания;
- `date` — дата снятия (проставляется автоматически, если не передана);
- `time` — время снятия (проставляется автоматически, если не передано).

**Методы:**

- `__str__()` — строковое представление вида `2026-09-15 10:00:00 - 100.0`;
- `from_data(data)` — создать объект из JSON (`@classmethod`);
- `to_dict()` — преобразовать объект в данные для JSON.

---

### `User` — пользователь

Объект представляет владельца счётчиков и показаний.

**Атрибуты:**

- `name` — имя пользователя;
- `meters: list[Meter]` — коллекция объектов `Meter`;
- `readings: list[Reading]` — коллекция объектов `Reading`.

**Методы:**

- `__str__()` — строковое представление пользователя.

---

## Взаимодействие объектов

- `Payment` строится на основе двух последних `Reading` счётчика.
- `Reading` содержит ссылку на `Meter` — характеристики прибора.
- `User` владеет коллекциями `Meter` и `Reading`.
- При загрузке JSON данные преобразуются в объекты через `from_data()`,
  а показания дополнительно связываются с объектами `Meter`.
- При сохранении объекты преобразуются обратно в JSON через `to_dict()`.
- Расчёт расхода и платежа идёт через `create_payment()`:
  `Payment → Reading → Meter`.

## Веб-интерфейс на Django

Проект имеет две версии:

- **консольная** (`main.py`);
- **веб-версия** (Django-проект).

Консольная версия сохранена и продолжает работать: классы пакета `models/`, функции `storage.py`, тесты `pytest` не изменены.

### Страницы веб-интерфейса

| URL | Назначение | View-функция |
|---|---|---|
| `/` | Главная: описание сервиса и навигация | `homepage.views.index` |
| `/meters/` | Список счётчиков | `meters.views.meters` |
| `/meters/<int:meter_id>/` | Карточка счётчика: характеристики, тариф, история показаний, рассчитанный платёж | `meters.views.meter_detail` |
| `/payments/` | Список платежей по всем счётчикам | `payments.views.payments` |
| `/payments/<int:meter_id>/` | Детальная страница платежа | `payments.views.payment_detail` |
| `/admin/` | Стандартная админка Django | `django.contrib.admin` |

Если счётчик с указанным `meter_id` не найден — возвращается страница с сообщением об ошибке и кодом **404**.

### Django-приложения

- **`homepage`** — главная страница.
- **`meters`** — страницы счётчиков и их показаний.
- **`payments`** — страницы платежей.

### Данные и переходный период

Django-представления **читают те же JSON-файлы**, что и консольное приложение (`data/meters.json`, `data/readings.json`), через функции `storage.py` и классы пакета `models/`.

Так как авторизация ещё не реализована, веб-интерфейс показывает **данные всех пользователей** одновременно. Это временное решение, которое будет исправлено переходом на Django ORM и разделением данных по пользователям в будущем.

## Django-шаблоны (ПР6)

Веб-часть проекта переведена с формирования HTML прямо в Python-коде на стандартную для Django схему:

```
View → Context → Template → HTML → HTTP-ответ
```

### Структура шаблонов

```
templates/                          # шаблоны уровня проекта
├── base.html                       # базовый шаблон
├── 404.html                        # страница 404
└── includes/
    └── navigation.html             # общая навигация

homepage/templates/homepage/
└── index.html                      # главная

meters/templates/meters/
├── meter_list.html                 # список счётчиков
└── meter_detail.html               # карточка счётчика

payments/templates/payments/
├── payment_list.html               # список платежей
└── payment_detail.html             # детальная страница платежа
```

Каталог шаблонов уровня проекта подключён в `settings.py` через параметр `DIRS` списка `TEMPLATES`:

```python
TEMPLATES = [
    {
        "BACKEND": "django.template.backends.django.DjangoTemplates",
        "DIRS": [BASE_DIR / "templates"],
        "APP_DIRS": True,
        ...
    },
]
```

### Базовый шаблон и наследование

Общая HTML-структура страницы (head, подключение стилей и скриптов, навигация, контейнер, подвал) вынесена в `templates/base.html`. Дочерние шаблоны используют наследование:

```django
{% extends "base.html" %}

{% block title %}Счётчики — Коммуналка{% endblock %}

{% block content %}
    <!-- содержимое конкретной страницы -->
{% endblock %}
```

### Включаемые шаблоны

Повторяющиеся фрагменты вынесены в отдельные шаблоны и подключаются через `{% include %}`:

```django
{% include "includes/navigation.html" %}
```

### Контекст шаблона

View-функции подготавливают данные и передают их в шаблон через словарь контекста:

```python
def meters(request):
    meters_list = _all_meters()
    return render(
        request,
        "meters/meter_list.html",
        {"meters": meters_list},
    )
```

В шаблоне данные доступны по имени переменной:

```django
{% for meter in meters %}
    {{ meter.name }}
{% endfor %}
```

### Циклы и условия

- `{% for %}` — перебор коллекций счётчиков, показаний, платежей.
- `{% empty %}` — обработка пустой коллекции (например, «Счётчиков пока нет»).
- `{% if %}` — условное отображение (наличие тарифа, найден ли счётчик, есть ли показания).

### Фильтры шаблонов

Применяются стандартные фильтры Django Template Language:

- `|length` — количество элементов в списке (`{{ meters|length }}`);
- `|default` — значение по умолчанию, если поле пустое
  (`{{ meter.name|default:"Без названия" }}`);
- `|floatformat:2` — форматирование числа с двумя знаками после запятой.

Фильтры используются только для представления данных, бизнес-логика остаётся в Python.

### Именованные URL и пространства имён

В каждом приложении задан `app_name`, а маршруты имеют имена:

```python
# meters/urls.py
app_name = "meters"
urlpatterns = [
    path("", views.meters, name="meters"),
    path("<int:meter_id>/", views.meter_detail, name="meter_detail"),
]
```

В шаблонах ссылки формируются через `{% url %}`, а не через жёстко заданные адреса:

```django
<a href="{% url 'meters:meter_detail' meter.id %}">
    {{ meter.name }}
</a>
```

Это позволяет менять URL-маршруты в одном месте, не затрагивая HTML.

## Формат хранения данных

Данные хранятся в JSON в каталоге `data/`. Для каждого пользователя используются отдельные записи.

### Пример записи счётчика

Файл `data/meters.json`:

```json
{
  "Пользователь": {
    "1": {
      "name": "Вода",
      "unit": "м^3",
      "tariff": 45.5
    }
  }
}
```

### Пример записи показания

Файл `data/readings.json`:

```json
{
  "Пользователь": [
    {
      "meter_id": 1,
      "value": 2324.0,
      "date": "2026-09-15",
      "time": "08:32:37"
    }
  ]
}
```

При загрузке JSON преобразуется в объекты `Meter` и `Reading`. Показания привязываются к соответствующим объектам `Meter` по `meter_id`. При сохранении объекты преобразуются обратно в JSON.

## Основные возможности

### Работа со счётчиками

Пользователь может просматривать список счётчиков, добавлять новый счётчик, указывать название и единицу измерения, устанавливать тариф, удалять счётчик вместе со всеми его показаниями.

### Работа с показаниями

Пользователь может добавлять новые показания с обязательной привязкой к счётчику, автоматически сохранять дату и время, просматривать историю, удалять показания, рассчитывать расход между последними показаниями.

### Работа с платежами

Для каждого счётчика можно рассчитать платёж по последним двум показаниям.

Стоимость рассчитывается по формуле:

```
платёж = расход × тариф
```

где:

- `расход` — разница между текущим и предыдущим показанием;
- `тариф` — стоимость одной единицы коммунального ресурса.

Расчёт выполняет класс `Payment` (файл `models/payments.py`).
